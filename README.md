# 일기장 · 기기 연동

[다이어리 열기](https://bokbok7717-eng.github.io/diary-main/)

## 사용

휴대폰과 PC에서 같은 이메일로 로그인합니다. 저장된 로그인이 있으면 로그인 안내를 띄우지 않고 세션을 확인한 뒤 열립니다. 확인 중에는 중립적인 대기 화면으로 기록을 가립니다. 로그아웃 또는 세션 만료 시에는 로그인 화면이 나타납니다. 다른 계정은 이전 계정의 기기 기록을 열 수 없습니다.

클라우드에 기록이 있으면 첫 기기에서도 자동으로 불러옵니다. 클라우드가 비어 있을 때만 ☁️ → **이 기기 자료 업로드**로 연결을 시작합니다. 저장 버튼을 누르면 약 0.5초 뒤 업로드를 시작하며, 열린 화면은 5초 간격 및 화면 복귀·재접속 때 변경을 확인합니다. 닫기 전 ☁️의 일기 연동 완료를 확인하세요. 브라우저가 강제로 종료되면 전송 전 기록은 해당 기기에 남습니다.

**글과 사진은 별도로 연동합니다.** 글·기록 목록을 먼저 반영하고 사진은 뒤에서 최대 4개씩 받습니다. 저장된 사진은 해시를 확인해 재사용합니다. 사진을 받거나 일부 사진 다운로드가 실패하더라도 글을 읽고 새 글을 저장할 수 있습니다. 일반 동기화는 페이지를 새로고침하거나 백업 다운로드를 열지 않습니다.

재접속 때 이미 저장된 사진은 네트워크로 다시 받지 않으며 전체 사진에 대한 `n/216` 로딩도 표시하지 않습니다. 사진 카운터는 실제로 새로 받아야 할 사진만 대상으로 표시합니다. 예를 들어 216장이 저장되어 있고 2장이 추가됐다면 새 사진 `0/2 → 2/2`만 표시합니다. 사진 캐시 확인이나 변경 없는 글 저장을 사진 다운로드·업로드로 표시하지 않습니다.

## 양쪽에서 편집했을 때

직전 동기화 기준을 IndexedDB에 기록하고 기기·클라우드의 변경을 비교합니다. 서로 다른 날짜의 기록, 같은 날짜라도 서로 다른 필드의 수정, 다른 ID의 커플 버킷 항목은 함께 보관합니다. 삭제도 기준과 비교해 반영합니다. 초안·저장하지 않은 편집 화면은 자동 교체하지 않습니다.

같은 부분을 다르게 수정했을 때만 ☁️에서 어느 쪽 내용을 사용할지 선택합니다. 겹치지 않은 내용은 유지하며 선택 전 원본 양쪽을 사용자별 IndexedDB의 복구 기록에 남깁니다. 선택 이후 클라우드가 또 바뀌었다면 새로 확인하도록 요청합니다. “저장된 내용 불러오기”도 같은 병합 절차를 사용하여 PC에서 아직 전송하지 못한 글을 통째로 덮어쓰지 않습니다.

기존 버전에서 처음 넘어올 때는 이전 버전 번호·해시가 기준을 복원할 수 있으면 그대로 사용합니다. 기준을 알 수 없는 경우에는 날짜별 기록을 보수적으로 합치고, 다르게 저장된 같은 기록은 직접 선택하도록 남깁니다.

## 저장과 권한

`diary_sync` 사용자별 행에는 글·설정과 비공개 사진 경로를 저장합니다. 사진은 `diary-photos` 버킷의 사용자 ID 아래 변경 불가능한 해시 경로로 저장합니다. 초안, 앱 잠금 PIN, 인증 토큰은 동기화하지 않습니다. 커플 모드도 같은 계정 안의 기록이며 다른 계정 간 공유 기능은 아닙니다.

업데이트는 사용자 ID와 마지막으로 읽은 `version`이 맞는 행에만 적용합니다. 다른 기기가 먼저 저장했으면 다시 읽어 병합합니다. 통신 실패가 이후 자동 동기화를 영구 중지시키지 않으며 재접속 시 다시 시도합니다. 로그아웃해도 로컬 원본은 삭제하지 않고 화면을 잠급니다.

## Supabase 설정

기존 프로젝트에서는 테이블·버킷·정책을 다시 만들 필요가 없습니다. 새로 설치할 때만 아래를 진행합니다.

- SQL Editor: `supabase/setup.sql`, `supabase/photo-storage.sql`
- Authentication → URL Configuration의 Site URL과 Redirect URLs: `https://bokbok7717-eng.github.io/diary-main/`
- 이메일 로그인 및 이메일 확인 활성화
- `cloud-sync.js`에는 프로젝트 URL과 **publishable key**만 사용. Secret/service_role 키는 넣지 않습니다.
- Supabase JS 2.49.4와 MIT 라이선스를 `vendor/`에 고정했습니다.

## 검증

`node --test tests/*.test.cjs`

회귀 테스트는 실제 동기화 엔진과 사진 모듈을 사용합니다. 휴대폰→PC→휴대폰 왕복, 양쪽의 오프라인 편집, 동시에 저장하는 경쟁, 같은 필드 충돌, 삭제·버킷 병합, 217개 사진 전송 대기 중 PC 글 저장, 재접속 시 사진 캐시 재사용, 사진 오류 뒤 글 저장, 초안 보호, 인증 복원 중 로그인 화면 깜빡임, 계정 변경 중 작업 취소를 다룹니다.

독립된 두 브라우저 origin의 로컬 검증에서는 가상 클라우드와 검증용 기록만 사용해 실제 편집·저장 버튼, IndexedDB, 글·사진 양방향 연동 및 재접속을 확인합니다. 이는 실제 휴대폰 하드웨어나 실제 두 계정의 권한 분리를 시험한 것과는 구분합니다. 개인 기록을 검증용 데이터로 덮어쓰지 않습니다.
